# Design items
- Carried inventory replaced by the host's after a rejoin (intake theme T6; -059, -061 items 1-2, -052 item 10). What a player actually carries lives in mainGamemode.playerContainer.propInventory -> saveSlot.GObjStack[0], restored from the host's save; the mod's per-player apply rewrites only the save-side projection arrays (inventoryData/equipment/hold), and ue_wrap/actors/inventory.h declares the live store read-only by construction, on purpose, pending open scope questions.
    needs: A scope decision on per-player state ownership, then either a live-store writer in ue_wrap or a pre-materialize edit of the host save's GObjStack[0] slot before the client's world boot. Also a decision on the miss branch: it currently fails safe by leaving the host's items ('NOT wiping'), which IS the inheritance. Blocked behind a four-peer rig run and behind the vitals constraint below.
- BUG-017 container contents contract layer (CONTEXT.md; corroborated in this drop by -031/Report 6 and -061 item 4, which adds the first persistence datum — supply-box loot lost on the NEXT save load).
    needs: No new work order — the reviewed direction ADD_CONTRACT_LAYER_KEEP_CURRENT_TRANSPORT stands. What this drop adds is scope: a named container class, an item count, the measured absence of both container_contents and PropSpawn, and a per-item ferry recovery route. Feed those into the contract design rather than re-opening it.
- Widening the OpenLevel veto's discriminator, or stopping registry_reaper classifying an involuntary tear as a player quit-to-menu (intake theme T4; Report 10, missing Bug 14, and the EXPLOSIONS capture -058).
    needs: T4 FIX A's instrumentation first — the discriminator's involvement in the reported events is INFERRED (H-A) and a travel path that never reaches UGameplayStatics::OpenLevel (H-B) is not excluded. Then a design decision between refusing the travel (product fix, must reuse the revive's screen cleanup but NOT its vitals/teleport writes, with the existing 8 s watchdog as escape) and merely not ending the session (smaller, strictly reduces the host-side blast radius). Also needs the reporter's missing Bugs 11-14, which the intake flags as a precondition for T4/T5 work.
- Which teardown edges must clear which per-peer state. T3's fix is bounded at Start(), but the underlying asymmetry is broader: Session::Stop() zeroes peerConns_ BEFORE CloseConnection so the status callback resolves slot -1, and upstream's new unresolved_pose_ledger (385c1eee) wires its ResetSlot to that same skipped edge and therefore inherits the identical hole.
    needs: An inventory of every per-peer array and its clearing edge, and a rule (clear-at-open, clear-at-close, or both) applied uniformly. Do this after T3's bounded fix lands, not instead of it.
- The host's deferred-destroy map leaks: 2104 entries armed and never drained in one session (up to 1041 in a single segment), with an O(n) dedupe scan on every arm and no size cap, on a host where HasLoadTailQuiesced is permanently false.
    needs: A decision whether the host should no-op these (matching its actual semantics) or bound-and-expire them. It is a leak, not a time bomb — but its log lines are what misled Report 3's author, and the lines mislabel the host's own arms as 'CLIENT'.
- T5-D2 / BUG-005: the client's console shows no disc for ~35 s because the Gap-I-1 fuzzy match rekeys and eid-binds an actor that already carries an armed incoming-destroy mark, and prop_echo_suppress exposes PeekIncomingSpawn but no PeekIncomingDestroy on either ref.
    needs: A runtime attribution of WHICH wire destroy armed that mark before adding the guard — otherwise the guard masks a symptom. Separately, the drive-slot INSERT lane applied 1 of ~16 attempts across all five logs (5 expired, 10 dropped slot-moved-on, 1 applied, 3 EJECTs); that systemic finding is the strongest lead for BUG-005 and is not explained by any trace here.
- Fire, explosion and device state have no replication path at all (Report 9 / -044: a client-lit barrel chain destroys 11 keyed props, kills and ignites a transformer, and the host 18 m away logs zero explosion/fire/damage, receiving only bare keyed destroys with eid=0). Adjacent: -039/Report 8, where the blackout mask and breaker restoration both sync with every bit ok=1 but the client's consoles stay dead because the keyed-subsystem index has no console/computer entry.
    needs: A subsystem-coverage decision: which native effect chains get a replication lane at all. This is the 'state syncs, native event effects don't' class (theme T3) and is not reachable by any bounded patch; Report 8 is the clean positive control for it.
- Cleaning surfaces does not sync in EITHER direction (-048, McJordan447) — the only symmetric failure in the drop, and a subsystem with no entry anywhere in the ledger.
    needs: A first source read to establish whether a lane exists at all. No trace covered it.
- Mod UI unreachable above 1080p (-050, intake theme T8): the bottom server rows cannot be clicked at 2560x1600 or 2560x1440 but work at default resolution.
    needs: A UI-layout owner and a direct repro — it is the only self-diagnosed, directly testable condition in the drop and needs no game session, only a resolution change. Nothing in BUG-001..020 covers UI layout.
- Four-peer topology coverage. Every structured report is host + one client, and the host log shows slot 1 with 49083 hits against 2-3 banner hits for slots 2-9 — only one client ever connected. Per-observer invisibility, global-instead-of-proximal audio and the inventory-replacement family are only fully expressible with three or more peers, and -061 states a full four-player lobby.
