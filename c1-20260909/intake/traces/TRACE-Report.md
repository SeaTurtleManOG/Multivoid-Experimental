## Defect
In the reporter's terms: a peer's game goes black and returns to the main menu, and the live coop session dies with it — the client is dumped out (Report 10, 22:44:20), or, when it happens to the host, every client is kicked too (host 00:03:34; Eggy's "boots everyone onto the main screen"); afterwards the host's lobby is still listed but every join burns a ~10 s timeout. In source terms there are three separable defects. (1) The OpenLevel veto's ONLY discriminator is the local pawn's `dead` bit read raw at a cached offset (death_revive.cpp:194-198 b150 / :174-178 3af5ddae, comment "not a death travel -- a quit, a save load, the backrooms"). Any travel to the menu with `dead == false` passes through, and registry_reaper's world-kind guard then classifies it as a player quit-to-menu and calls net_pump::FleeAfterNativeMenuTravel -> Session::Stop() (registry_reaper.cpp:213-234 b150 / :130-147 3af5ddae; net_pump.cpp:326-330 / :198-202). On the host that Stop() reaches every client as "HOST CLOSED OUR CONNECTION (reason: session stop)" and flees them to the menu (net_pump.cpp:641-647 / :420-426) — measured on the client at 00:03:33. (2) The reporter's headline finding — "asymmetric death handling: the client's death produced zero death_revive trace, so arming is host-only" — is REFUTED. Arming has no role gate anywhere: Install runs on the unconditional timeline tick (session_runtime.cpp:118), Tick is called for both roles from one block (net_pump.cpp:726 / :475), and the arm predicate is `installed && verbsOk && session.running() && deadByte>=0` (death_revive.cpp:651-667 / :551-567) with no host term. What the client's silence means is that the local pawn's `dead` bit never rose — i.e. the thing that ended the client's game was not a `dead`-flagged death. (3) The reporter's finding B mechanism — "the P2P listener died with the session" — is also REFUTED: the host session never stopped (first "net: session stopped" is 22:47:50, three minutes after the failed joins) and hListen_ is closed only inside the Stop path (session_start.cpp:489-490 / :404). What was dead was the host's signaling TCP flow to the relay: SignalingClient::Poll has no keepalive, no SO_KEEPALIVE and no liveness timer (signaling_client.cpp:445-537 / :395-476), so a silently half-open flow is indistinguishable from an idle healthy one and the process logs nothing; meanwhile the lobby listing is kept warm over a completely separate channel, a fresh HTTP POST /v1/heartbeat every 30 s (lobby_announcer.cpp:102-130 / :100-128). Listed-but-unreachable is the direct product of those two channels having different liveness properties.

## Proposed fix
Three fixes, in the order I would land them. Only the first is READY today; it is also the one that converts the reporter's open question into a measurement.

FIX A (READY, zero behaviour change) — make the seam say what it saw.
Files: src/votv-coop/src/ue_wrap/engine/level_travel.cpp (OpenLevelDetour, :68-79 b150 = :68-79 3af5ddae) and src/votv-coop/include/coop/player/death_revive.h (add TravelsSeen(), already present on 3af5ddae at :55). On the PASS-THROUGH branch — the branch taken when no veto is published or the veto declined — emit one UE_LOGW naming the four terms the veto evaluated: armed, session running, pawn live-by-index, and the raw `dead` byte value it read. All four are already loaded in VetoOpenLevel (death_revive.cpp:180-198 / :161-178), so publishing them costs one extra atomic load; the veto's data-only contract (no UFunction dispatch, no engine allocation, no game-thread lock) is preserved because a log call is none of those. Rate-limit to one line per travel — travels are a handful per session (SeenCount was 0 for the whole client session by construction of the log). Also surface SeenCount/VetoCount in the existing periodic `net stats:` line so a session that never reaches the seam is visible without a repro.
Why it cannot regress the legitimate path: it adds no branch that can change the detour's return value; the pass-through still calls the trampoline unconditionally.
Falsifier for FIX A: if, on a reproduced explosion tear, the new line does NOT appear at the moment of the world_identity change, then the travel never entered UGameplayStatics::OpenLevel and DEATH_ARC row 6.1.3's "one detour covers both" is incomplete for this content — the seam itself would then be in the wrong place, and no discriminator change could ever help.

FIX B (NEEDS_RUNTIME, gated on FIX A's answer) — widen the discriminator, not the seam.
Only if FIX A shows the travel reaching the detour with dead==0. The correct shape is NOT "arm the client" (the client already arms identically) and NOT "refuse every menu travel" — that inverts the fail-open direction the design deliberately chose, and refusing a travel the revive cannot answer is exactly the H1 shape death_revive.h:31-39 was built to avoid. The bounded shape is an AUTHORSHIP term: the mod already knows about its own flees (they call Session::Stop() before travelling, so they arrive with running()==false and pass through untouched) and its menu layer already owns the pause-menu / Main Menu button surface. Latch "the local player asked to leave" there; a gameplay->MENU travel in a live session with no such latch and with the pawn alive is an INVOLUNTARY tear. Two sub-options, and the choice needs the FIX A data: (B1) refuse it and hold the world, reusing the revive's screen cleanup (black screen / damage indicator / bloodLoss) but NOT the vitals/teleport writes, since the player is not dead — with the existing 8 s watchdog (death_revive.cpp:729-758 / :631-655) as the unconditional escape. (B2) let the travel proceed but stop registry_reaper from CLASSIFYING it as a quit, so the host does not Stop() the session and eject everyone; the host's world really is gone, so this only helps if the host can re-open. B2 is smaller and strictly reduces harm on the host side (it is what turns Eggy's "boots everyone" back into "the host left"); B1 is the product fix. Neither may ship before FIX A tells us which travel we are refusing.
Why it cannot regress the legitimate path: the `dead` fast path is untouched, so both host deaths in these logs still arm, refuse and revive exactly as measured; a genuine player quit carries the authorship latch and still passes.

FIX C (READY, independent of A/B) — stop the host being listed while unreachable.
File: src/votv-coop/src/coop/net/signaling_client.cpp, ConnectLocked (:278-330 b150 / :246-295 3af5ddae). Set SO_KEEPALIVE on the signaling socket and, on Windows, a short idle via WSAIoctl SIO_KEEPALIVE_VALS (e.g. 30 s idle, 5 s interval). That is purely local — it needs no relay change and no wire-protocol change — and it converts a silent half-open flow into a recv error, which the EXISTING reconnect path already handles (Poll's `sock_ == kInvalidSock` branch, :449-456 / :399-406, backoff 5 s, and ConnectLocked re-greets so the relay re-issues its nonce and re-registers the identity). Add, in the periodic `net stats:` line, the age of the signaling flow's last inbound byte, so "listed but unreachable" becomes visible before a player burns two 10 s timeouts. Optional and better, but it needs the relay: an application-level ping line every ~30 s.
Why it cannot regress the legitimate path: TCP keepalive probes are invisible to the line protocol; the only new outcome is that a flow which was already dead is now reported dead, and the code path that follows is the one already taken on `server closed connection`.
Falsifier for FIX C: leave a host idle at the menu-listed state for >60 min and dial it. On b150 the host logs nothing and the client times out (measured, twice). With FIX C the host must log `signaling: recv error … -- will reconnect` followed by `signaling: connecting to …` and `answered the relay's registration challenge` within one backoff, and the next dial must produce `signaling: creating signaling session for peer` on the host. If the dial still fails after a proven fresh registration, the fault is the master/relay side, not this socket.

## Standalone test shape
Two offline tests plus one harness change; none needs the game.

T1 — the discriminator's coverage, as a pure unit test on the veto's decision function.
